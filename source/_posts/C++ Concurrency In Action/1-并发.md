### 多线程 vs. 多进程具体开销对比表

| 开销类别 | 具体操作 | 多进程（开销大） | 多线程（开销小） |
| :--- | :--- | :--- | :--- |
| **创建与销毁开销** | **分配内存空间** | 需要为新的**代码段、数据段、堆、栈**分配一个全新的、独立的虚拟地址空间。这是一个重量级操作。 | **共享**父进程的地址空间。只需在进程已有的堆栈空间中分配一个**独立的栈空间**（通常较小，如 8MB）供线程私有使用。 |
| | **创建内核对象** | 需要创建一个完整的**进程控制块（PCB）**，用于管理进程的复杂状态和资源。 | 只需创建一个相对简单的**线程控制块（TCB）**，主要记录寄存器、栈指针等执行状态。 |
| | **资源初始化** | 需要初始化或复制很多资源，如文件描述符表、信号处理程序、独立的内存页表等。 | 大部分资源（如打开的文件、全局变量）**共享**父进程的，初始化工作极少。 |
| **上下文切换开销** | **切换内存地址空间** | **必须切换**。需要加载新进程的页表全局目录（CR3寄存器），导致**TLB（快表）被全部刷新/失效**。这是最大的性能损失点。 | **无需切换**。线程在同一进程内，共享同一地址空间，TLB缓存保持有效，CPU缓存命中率高。 |
| | **保存/恢复硬件上下文** | 需要保存和恢复所有的CPU寄存器状态、浮点寄存器、SSE/AVX寄存器等。 | 同样需要保存和恢复寄存器状态，但**总量和进程切换基本一致**。 |
| | **CPU缓存效率** | 切换后，新进程的数据和指令在CPU高速缓存（L1/L2/L3）中的命中率极低，缓存几乎完全失效。 | 由于地址空间不变，切换后线程访问的代码和数据有很大概率仍在CPU缓存中，效率极高。 |
| | **涉及内核态操作** | 进程切换**绝对需要**从用户态陷入内核态，由操作系统内核完成，是系统调用。 | 线程切换也**通常需要**进入内核态（由内核线程实现时）。但在**用户态线程**（如协程）模型中，开销可以进一步降低。 |
| **通信开销** | **数据传递** | 必须通过操作系统内核的**进程间通信（IPC）** 机制，如：<br> • **管道/消息队列**：需要将数据从发送进程用户空间拷贝到内核缓冲区，再从内核缓冲区拷贝到接收进程用户空间（**两次拷贝**）。<br> • **共享内存**：虽避免了拷贝，但需要复杂的同步机制（如信号量）来管理，设置复杂。 | 由于共享全局变量和堆内存，线程间通信**直接通过读写共享内存**即可完成，速度极快（纳秒级）。 |
| | **同步开销** | 进程间的同步原语（如信号量、文件锁）是内核对象，每次调用（如`sem_wait`）都是**系统调用**，需要从用户态切换到内核态，开销大。 | 线程间的同步原语（如互斥锁、读写锁）在无竞争的情况下，通常可以通过**用户态的原子操作**（如CAS）实现，无需进入内核态，开销小。只有在发生锁竞争时，才可能陷入内核。 |
| **资源占用开销** | **内存占用** | 每个进程都有独立的内存空间，即使通过写时复制（Copy-on-Write）技术，初始开销也远大于线程。 | 线程主要占用其私有栈空间（可设置，通常几MB），共享代码段和堆，内存利用率高。 |

### 多进程的优势：稳定性和真正的并行

尽管多线程开销小，但多进程并非一无是处，它在以下场景中是不可替代的：

1.  **更好的稳定性和隔离性**： 这是多进程最大的优点。一个进程崩溃不会影响其他进程。例如，Chrome浏览器为每个标签页开一个进程，这样即使某个网页崩溃，也不会导致整个浏览器关闭。
2.  **真正的并行（在多核CPU上）**： 在Python等有**全局解释器锁（GIL）** 的语言中，多线程无法利用多核优势实现真正的并行计算。但对于CPU密集型任务，使用多进程可以将任务分配到多个CPU核心上同时运行，从而大幅提升性能。

### 总结与选择建议

| 任务类型 | 推荐方案 | 理由 |
| :--- | :--- | :--- |
| **I/O密集型**（如网络请求、文件读写） | **多线程** | I/O操作会阻塞线程，但不会占用CPU。使用多线程可以在一个线程等待I/O时，让出CPU给其他线程执行，高效利用CPU时间。创建和切换开销小的优势得以体现。 |
| **CPU密集型**（如数学计算、图像处理） | **多进程（尤其在Python中）** | 需要充分利用多核CPU进行计算。在无GIL的语言中（如Java、C++），可以用多线程；但在有GIL的语言中，必须用多进程才能实现并行。 |
| **需要高稳定性/隔离性** | **多进程** | 避免单个组件的错误导致整个应用程序崩溃。 |
